# Развёртывание на VPS

Инструкция под Ubuntu 22.04/24.04 (для Debian команды те же). Проверялась на
тарифе reg.ru Free Tier C1-M1-D10 — 1 ядро, 1 ГБ памяти, 10 ГБ диска. Боту
этого хватает с большим запасом: он держит одно соединение с Discord и пишет
в SQLite.

Все команды с префиксом `PS>` выполняются на вашем компьютере в PowerShell,
остальные — на сервере.

---

## 1. Что нужно перед началом

Из панели reg.ru: **IP-адрес** сервера и **пароль root** (приходит на почту или
показывается при создании). Дождитесь, пока статус сменится с «Создается» на
«Активен» и появится IP.

---

## 2. Первое подключение

```
PS> ssh root@ВАШ_IP
```

При первом подключении SSH спросит про отпечаток ключа — ответьте `yes`.

Обновите систему:

```
apt update && apt upgrade -y
```

### Отдельный пользователь вместо root

Работать от root постоянно не нужно — одна опечатка в команде обходится дорого.

```
adduser bot
usermod -aG sudo bot
```

Придумайте пароль, остальные вопросы можно пропустить (Enter).

Дальше подключайтесь уже под ним: `ssh bot@ВАШ_IP`.

### Файрвол

Открыт должен быть только SSH — бот сам никаких портов не слушает, он
подключается к Discord исходящим соединением.

```
sudo ufw allow OpenSSH
sudo ufw enable
```

---

## 3. Docker

```
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
```

Переподключитесь по SSH, чтобы группа применилась, и проверьте:

```
docker run --rm hello-world
```

Если вывелось «Hello from Docker!» — готово.

---

## 4. Перенос проекта

На **вашем компьютере**, в PowerShell.

### Сначала остановите локального бота

Это обязательно: пока он работает, часть данных лежит в WAL-файле рядом с базой,
и копия получится неполной. `Ctrl+C` в окне, где он запущен.

### Скопируйте проект

```
PS> cd C:\Projects
PS> scp -r discord-acb\bot discord-acb\tools discord-acb\assets discord-acb\tests bot@ВАШ_IP:~/discord-acb/
```

Если `scp` ругается, что каталога нет — создайте его на сервере заранее:
`mkdir -p ~/discord-acb`.

Отдельно файлы из корня:

```
PS> cd C:\Projects\discord-acb
PS> scp Dockerfile docker-compose.yml deploy.sh requirements.txt requirements-dev.txt pytest.ini README.md DEPLOY.md .env.example .gitignore bot@ВАШ_IP:~/discord-acb/
```

Два файла в этом списке легко проглядеть, а без них дальше ничего не работает:
из `.env.example` на следующем шаге делается `.env`, а `deploy.sh` — это то, что
запускает автовыкат из раздела 8.

`scp` не переносит бит запуска, так что на сервере его нужно вернуть:

```
chmod +x ~/discord-acb/deploy.sh
```

### Перенесите накопленную статистику

База — один файл. Вместе с ним нужно забрать `-wal`, если он остался:

```
PS> scp discord-acb\data\activity.db* bot@ВАШ_IP:~/discord-acb/data/
```

Каталог создайте заранее: `mkdir -p ~/discord-acb/data`.

Если статистику переносить не хотите — просто не копируйте, база создастся с нуля.

### Конфигурация

`.env` намеренно не копируется вместе с остальным: в нём токен. Создайте его на
сервере вручную.

```
cd ~/discord-acb
cp .env.example .env
nano .env
```

Впишите `DISCORD_TOKEN`, поставьте `AGG_TIMEZONE=Europe/Moscow` и
`ENABLE_PRESENCE_TRACKING=true`. Сохранить — `Ctrl+O`, `Enter`, выйти — `Ctrl+X`.

Закройте файл от посторонних:

```
chmod 600 .env
```

---

## 5. Запуск

```
cd ~/discord-acb
docker compose up -d --build
```

Первая сборка займёт пару минут. Проверьте логи:

```
docker compose logs -f
```

Должно быть `Вошли как Большой Брат#...` и `Синхронизировано активных
голосовых сессий: N`. Выйти из просмотра логов — `Ctrl+C`, бот продолжит работать.

**Важно:** убедитесь, что локальный бот на вашем компьютере выключен. Два
экземпляра с одним токеном будут мешать друг другу и задваивать статистику.

Автозапуск после перезагрузки сервера настраивать не нужно — `restart:
unless-stopped` в `docker-compose.yml` поднимет контейнер сам.

---

## 6. Повседневное

| Задача | Команда |
|---|---|
| Логи в реальном времени | `docker compose logs -f` |
| Последние 100 строк | `docker compose logs --tail 100` |
| Перезапустить | `docker compose restart` |
| Остановить | `docker compose stop` |
| Статус | `docker compose ps` |

### Обновление кода

Руками копировать файлы не нужно — для этого есть
[раздел 8](#8-авторазвертывание): `deploy-local.ps1` с вашей машины или выкат
по push. Оба варианта сами пересобирают контейнер и проверяют, что бот
поднялся.

Если всё же скопировали файлы вручную, пересобрать нужно так:

```
docker compose up -d --build
```

### Бэкап статистики

Самое ценное — `data/activity.db`. Останавливать бота для копии не обязательно,
но так надёжнее:

```
docker compose stop
tar -czf ~/activity-backup-$(date +%F).tar.gz -C ~/discord-acb data
docker compose start
```

Забрать архив на компьютер:

```
PS> scp bot@ВАШ_IP:~/activity-backup-*.tar.gz C:\Projects\
```

Делайте это хотя бы раз в месяц: восстановить историю голосовой активности
из Discord невозможно, её нигде больше нет.

---

## 7. Если что-то не так

**Контейнер перезапускается по кругу.** Смотрите `docker compose logs --tail 50`.
Чаще всего — неверный токен или не включённые привилегированные intents.

**«Discord отклонил привилегированные intents».** В Developer Portal не включены
Presence и Server Members, а в `.env` стоит `ENABLE_PRESENCE_TRACKING=true`.
Либо включите интенты, либо поставьте `false`.

**Карточки профиля выглядят плохо.** Не нашёлся шрифт. В образе стоит
`fonts-dejavu-core`, но если что-то пошло не так — проверьте
`docker compose logs | grep -i шрифт`.

**Мало места на диске.** Старые образы Docker занимают место:
`docker system prune -a` (удалит неиспользуемые образы, данные бота не тронет).

---

## Про сеть

Бот не требует ни доменного имени, ни открытых портов, ни SSL. Он сам
подключается к Discord по исходящему WebSocket. Единственный входящий доступ,
который нужен, — SSH для вас.

---

## 8. Авторазвертывание

Два уровня — выбирайте по вкусу, они не мешают друг другу.

### Вариант А: одна команда с вашей машины

Ничего настраивать не нужно, GitHub не требуется. Скрипт прогоняет тесты,
копирует исходники и пересобирает контейнер на сервере:

```
PS> .\scripts\deploy-local.ps1 -Server bot@ВАШ_IP
```

Первый раз — вместе с накопленной локально статистикой:

```
PS> .\scripts\deploy-local.ps1 -Server bot@ВАШ_IP -WithDatabase
```

`.env` и база на сервере не трогаются (кроме явного `-WithDatabase`), так что
токен и статистика переживают любое количество выкатов. Если тесты падают —
скрипт останавливается и ничего не отправляет.

### Вариант Б: выкат по push в GitHub

Код уезжает на сервер сам, как только вы отправили коммит в `main` и тесты
прошли. Настраивается один раз.

**1. Репозиторий.** Публичный — в нём только код:

```
PS> gh repo create discord-activity-bot --public --source=. --push
```

История сервера в репозиторий не попадает: она лежит в `data/activity.db` на
самом сервере, а этот каталог вместе с `.env` перечислен в `.gitignore`.
Приватный репозиторий тоже подойдёт — тогда вместо `--public` укажите
`--private`, остальные шаги те же.

**2. Ключ для доступа сервера к репозиторию.** На сервере:

```
ssh-keygen -t ed25519 -C "deploy" -f ~/.ssh/id_ed25519 -N ""
cat ~/.ssh/id_ed25519.pub
```

Выведенную строку добавьте на GitHub: репозиторий → Settings → Deploy keys →
Add deploy key. Права на запись не нужны.

Клонируйте проект на сервер (если разворачивали через `scp` — перенесите
`.env` и `data/` в новый каталог):

```
git clone git@github.com:ВАШ_ЛОГИН/discord-activity-bot.git ~/discord-acb
```

**3. Ключ для доступа GitHub Actions к серверу.** На вашей машине:

```
PS> ssh-keygen -t ed25519 -C "github-actions" -f $env:USERPROFILE\.ssh\deploy_key -N '""'
PS> type $env:USERPROFILE\.ssh\deploy_key.pub | ssh bot@ВАШ_IP "cat >> ~/.ssh/authorized_keys"
```

**4. Секреты репозитория.** Значение `SSH_KNOWN_HOSTS` получите командой
`ssh-keyscan ВАШ_IP` и вставьте вывод целиком.

```
PS> gh secret set SSH_KEY < $env:USERPROFILE\.ssh\deploy_key
PS> gh secret set SSH_HOST
PS> gh secret set SSH_USER
PS> gh secret set SSH_KNOWN_HOSTS
PS> gh secret set DEPLOY_PATH
```

`DEPLOY_PATH` — путь на сервере, например `/home/bot/discord-acb`.

Дальше выкат сводится к обычному:

```
PS> git push
```

GitHub прогонит тесты на Python 3.12, 3.13 и 3.14 и, если зелены все три
версии, зайдёт по SSH и выполнит
`deploy.sh`. Ручной перевыкат без коммита — вкладка Actions → «Развёртывание» →
Run workflow.

### Что делает `deploy.sh`

Один и тот же скрипт используют оба варианта: подтягивает код (если каталог под
git), пересобирает контейнер, чистит старые образы и ждёт, пока в логах появится
`Вошли как`. Если за 5 минут бот не вошёл — скрипт завершается с ошибкой и
печатает логи, чтобы неудачный выкат не выглядел успешным.

Запас именно такой из-за первого запуска после обновления схемы: бот
достраивает недостающие индексы и собирает статистику планировщика **до**
того, как войдёт в Discord. На базе в пару гигабайт это десятки секунд, на
небыстром диске VPS — больше. Выглядит как зависший выкат, но это разовая
работа: следующие запуски снова занимают секунды.

Ни один из вариантов не трогает `.env` и `data/` — токен и статистика остаются
на сервере при любом обновлении кода.
